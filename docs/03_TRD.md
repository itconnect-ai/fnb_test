## 1. 기술 구성 (Technology Stack & Architecture)

별도의 백엔드 서버나 유료 API 없이, 사장님의 브라우저 환경에서 완전히 독립적으로 동작하며 향후 **GitHub 저장소 푸시 및 Vercel 무료 정적 웹 호스팅 배포**가 완벽하게 가능하도록 설계합니다.

```
[ 브라우저 클라이언트 (SPA) ]
┌─────────────────────────────────────────────────────────────┐
│  Presentation Layer (UI / Views)                            │
│  - Vanilla HTML5 + CSS3 (High-Density Retail Design System) │
│  - Icons: Google Material Symbols Outlined (CDN)            │
│  - Fonts: Noto Sans (Tabular Numbers font-variant 지원)      │
├─────────────────────────────────────────────────────────────┤
│  Application Layer (Router & Controllers)                   │
│  - Pure Client-side SPA Router (화면 깜빡임 없는 뷰 전환)   │
│  - Event-driven Reactive Store (상태 변경 시 자동 리렌더링) │
├─────────────────────────────────────────────────────────────┤
│  Domain & Service Layer (Business Engines)                  │
│  - FRD 5대 계산 공식 엔진 (calculations.js)                 │
│  - SheetJS (xlsx) 브라우저 엑셀 파서 & 생성 엔진            │
├─────────────────────────────────────────────────────────────┤
│  Data Layer (Local Persistence)                             │
│  - Primary: IndexedDB (대용량 445일치 데이터 영구 보존)     │
│  - Secondary: LocalStorage (UI 탭 상태, 필터 설정 등)       │
└─────────────────────────────────────────────────────────────┘
```

* **빌드 도구 & 개발 환경**:
  * **Vite**: 초고속 로컬 개발 서버 및 정적 번들 빌드 (`npm run dev`, `npm run build`).
  * 빌드 결과물이 순수 정적 파일(`dist/`)로 생성되어 Vercel, GitHub Pages, Netlify 어디에나 설정 없이 즉시 배포 가능.
* **UI/스타일링**:
  * `design/DESIGN.md` 및 `design/code.html` 시안의 100% 충실한 구현.
  * 단일 픽셀 테두리(`1px solid #E2E8F0`), 고밀도 표(36px 행 높이), 시인성 높은 상태 뱃지(긴급/적정/주의).
* **엑셀 처리 라이브러리**:
  * **SheetJS (`xlsx`)**: 브라우저 메모리 상에서 원본 엑셀 파일을 읽고(파싱), 11개 시트로 구성된 정규 엑셀 백업 파일을 즉시 생성하는 업계 표준 라이브러리.
* **로컬 영구 저장소**:
  * **IndexedDB**: 445일치(6,112건 판매, 1,515건 재고, 3,560건 비용)의 대용량 데이터를 브라우저 5MB 용량 한계 없이 안전하게 영구 저장.

## 2. 데이터 흐름 (Data Flow)

모든 데이터는 브라우저 내부에서 완결되며, 외부 서버로 사장님의 매출이나 원가 정보가 유출되지 않습니다.

```
[ 앱 실행 (index.html) ]
       │
       ▼
[ IndexedDB 초기화 검사 ]
  ├─ 기존 데이터 있음 ──> IndexedDB에서 11개 데이터셋 로드
  └─ 데이터 없음(첫 실행) ─> data/매장운영데이터.json 자동 초기 로드 ──> IndexedDB 저장
       │
       ▼
[ 메모리 상태 저장소 (In-Memory State Store) ]
  ├─ 모든 화면(마감 홈, 메뉴 수익성, 예상 손익, 재고)에 최신 데이터 동기화
       │
       ▼
[ 사장님 사용자 인터랙션 발생 ]
  ├─ 1. 일일 마감 입력: 판매량/입고 등록 ──> Store 업데이트 ──> 수불부 연쇄 계산 ──> IndexedDB 비동기 저장 ──> UI 자동 갱신
  ├─ 2. 엑셀 백업: Store 11개 데이터셋 ──> SheetJS 가공 ──> '프렙카페_운영백업_날짜.xlsx' 브라우저 다운로드
  └─ 3. 엑셀 복원: 사장님이 .xlsx 업로드 ──> 무결성 검증 ──> Store 전체 덮어쓰기 ──> IndexedDB 동기화 ──> 화면 새로고침
```

## 4. 가져오기와 저장·백업·복원 (Import, Storage, Backup, Restore)

### 4.1 가져오기 (Excel Import)
* **드래그 앤 드롭 및 파일 업로드 지원**: 마감 입력 화면에서 사장님이 엑셀 파일을 올리면 브라우저의 `FileReader`와 `SheetJS`를 통해 메모리에서 즉시 파싱.
* **양식 호환성**: 원본 `매장운영데이터.xlsx`의 컬럼명 및 시트 구조와 100% 호환. 당일 판매분만 적힌 간이 엑셀도 자동 감지하여 처리.

### 4.2 영구 저장 (Storage Engine)
* **IndexedDB 데이터베이스명**: `PrepCafeOperationsDB` (버전 1).
* **Object Stores (11개)**:
  `suppliers`, `materials`, `menus`, `recipes`, `price_history`, `calendar`, `sales`, `opening_inventory`, `inventory_events`, `monthly_expense_plan`, `expenses`.
* 사장님이 입력을 완료하는 즉시 비동기 트랜잭션으로 커밋되어, 브라우저 창을 닫아도 안전하게 보존됨.

### 4.3 백업 (Export Backup)
* 사장님이 `[전체 데이터 Excel 백업]` 버튼을 누르면:
  1. IndexedDB에 있는 11개 테이블 데이터를 추출.
  2. SheetJS를 통해 11개의 탭(시트)으로 구성된 정규 엑셀 워크북(`.xlsx`) 생성.
  3. `프렙카페_운영백업_YYYYMMDD_HHMM.xlsx` 파일명으로 브라우저 즉시 다운로드 실행 (0.5초 소요).

### 4.4 복원 (Restore)
* 사장님이 백업 엑셀 파일을 업로드하면:
  1. 11개 필수 시트 존재 여부 및 주요 헤더 컬럼 검증.
  2. 검증 성공 시 확인 대화상자 표시: *"기존 데이터를 업로드한 파일로 완전히 교체하시겠습니까?"*
  3. 승인 시 기존 IndexedDB 데이터를 일괄 갱신하고 화면을 자동 새로고침하여 즉시 반영.

### 4.5 빈 매장 시작 지원 (No Data Mode)
* 자료가 전혀 없는 상태에서도 사장님이 직접 메뉴와 재료를 등록하고 오늘 판매부터 시작할 수 있도록 **"초기화(빈 매장으로 시작)"** 기능과 **"샘플 데이터 불러오기"** 기능을 함께 제공합니다.

## 5. 날짜·단위·반올림·중복·저장 실패 처리

### 5.1 날짜 처리 (Date Standard)
* **표준 형식**: `YYYY-MM-DD` (ISO-8601 문자열 기준).
* **타임존 왜곡 방지**: JavaScript의 `Date` 객체 변환 시 발생할 수 있는 시차 오차(UTC vs KST 자정 밀림 현상)를 방지하기 위해, 모든 날짜는 **문자열 기반의 직접 파싱 및 비교 연산**을 수행합니다.

### 5.2 단위 일관성 (Units)
* 식재료 단위: `g`, `ml`, `개` 엄격 구분.
* 레시피 연산 시에는 부동소수점 오차를 방지하기 위해 정수 환산 후 연산(`Math.round(val * 100) / 100`).
* 화면 표시 시: 수량은 정수(필요시 소수점 1자리), 금액은 원 단위 정수로 포맷팅.

### 5.3 반올림 기준 (Rounding Rules)
* **최종 금액 표시**: **사사오입 반올림 (`Math.round`)** 적용. (단, 1.5% 결제수수료 및 개당 마진 계산 과정에서는 소수를 유지하여 오차 누적 방지)
* **발주 추천 수량**: 무조건 **올림 (`Math.ceil`)**을 적용하여, 패키지 단위 묶음 주문 시 재고 부족이 발생하지 않도록 보장.

### 5.4 중복 입력 처리 (Deduplication)
* **판매 기록 식별자**: `(일자 + 메뉴ID + 채널)`을 복합 식별자로 사용.
  * 같은 날짜에 동일 메뉴/채널 판매 수량이 다시 입력되면: 덮어쓰기(수정)할지 기존 수량에 합산할지 안내 팝업 제공.
* **자동 채번 ID**: 판매ID(`S000001` 형식), 전표ID(`E000001` 형식)는 기존 최대 번호를 추적하여 자동 순번 채번.

### 5.5 저장 실패 및 비상 처리 (Failure Handling & Safety Net)
* 사장님이 '시크릿 브라우징(Private Mode)'을 사용 중이거나 디스크 용량이 꽉 차서 IndexedDB 저장이 차단되는 경우:
  * 1단계: 메모리 상에 변경 데이터를 즉시 보존하여 화면이 튕기지 않게 보호.
  * 2단계: 화면 상단에 경고 배너 팝업: *"⚠️ 브라우저 저장소 접근이 제한되어 있습니다. 입력 내용을 보존하기 위해 비상 엑셀 백업 파일을 다운로드합니다."* 안내 후 엑셀 다운로드 자동 트리거.

## 6. 기술 대안 비교 (Trade-off Analysis)

| 영역 | 채택한 기술 (Selected) | 포기한 대안 (Abandoned) | 선택 이유 및 포기 사유 (비개발자 관점) |
|---|---|---|---|
| **저장소** | **브라우저 IndexedDB** | LocalStorage | LocalStorage는 약 5MB 용량 제한이 있어 445일치 데이터(약 3.5MB)에 향후 데이터가 조금만 쌓여도 저장이 멈추는 치명적 결함이 있음. IndexedDB는 수백 MB까지 무제한 저장 가능. |
| **배포/호스팅** | **Vite 기반 정적 SPA**<br>(Vercel / GitHub) | Node.js + DB 서버<br>(AWS, Heroku 등) | 별도 서버와 DB를 두면 매달 서버비(월 1~5만 원)와 서버 다운/보안 관리 부담 발생. 정적 SPA는 **평생 100% 무료 호스팅**이 가능하고 서버가 다운될 염려가 없음. |
| **프레임워크** | **Vanilla JS (모듈형)** | 무거운 React/Angular | 본 시스템은 실시간 통신이나 대규모 팀 개발이 아니며, 빠른 첫 로딩(1초 미만)과 깔끔한 단일 파일 유지보수가 핵심임. 프레임워크 오버헤드를 없애고 반응 속도를 극대화. |
| **엑셀 처리** | **SheetJS (xlsx) 클라이언트 처리** | 서버 엑셀 변환 API | 사장님의 민감한 매장 매출/원가 엑셀 데이터가 외부 서버로 전송되지 않고 사장님 PC 브라우저 안에서 100% 안전하게 처리됨. |

## 7. 기기 간 공유 등 사용상 한계 (System Boundaries)

> [!IMPORTANT]
> **기기 간 자동 동기화의 한계 안내**
> * 본 프로그램은 별도의 중앙 클라우드 데이터베이스 서버를 두지 않고, 사장님의 **현재 PC/노트북 브라우저 안에서만 안전하게 동작**합니다.
> * 따라서 **"매장 카운터 포스기에서 입력한 내용이 집 노트북이나 사장님 스마트폰에 자동으로 실시간 연동되지 않습니다."**
> * **기기 변경/이동 방법**:
>   1. 매장 PC에서 `[데이터 백업]` 버튼을 눌러 `백업.xlsx` 파일을 다운로드합니다. (USB 또는 카카오톡 나에게 보내기)
>   2. 집 노트북이나 다른 기기에서 프로그램을 열고 `[데이터 복원]`을 눌러 해당 엑셀 파일을 올리면 **1초 만에 100% 완벽하게 이전**됩니다.

## 8. 자동 검사와 사장님이 화면에서 확인할 부분

### 8.1 개발 완료 시 자동 검증 (Automated Tests)
1. **데이터 무결성 테스트**:
   - `매장운영데이터.xlsx`의 445일치 실적을 불러와 수불부 시뮬레이션 시 단 하루도 음수 재고가 발생하지 않는지 검증.
2. **계산 엔진 단위 테스트**:
   - 아메리카노 테이크아웃 할인 시 마진율 80.8% 산출 검증.
   - 직전 4주 요일별 평균 매출 프로젝션 공식의 오차 0원 검증.
   - 발주점 이하 품목의 팩/박스 단위 올림(Ceil) 수량 일치 검증.
3. **엑셀 왕복(Round-trip) 검증**:
   - 현재 데이터를 엑셀로 백업 ➔ 복원했을 때 1원, 1g의 오차도 없이 100% 원상 복구되는지 검증.

### 8.2 사장님이 화면에서 직접 확인하실 부분 (Checkpoints)
1. **마감 홈 첫인상**:
   - 프로그램을 열었을 때 바로 오늘 순매출, 오늘 순익, 그리고 붉은색 발주 알림(우유 N박스, 원두 N봉)이 직관적으로 보이는가?
2. **일일 마감 입력의 편리함**:
   - 오늘 아메리카노 20잔, 라떼 10잔을 입력했을 때 5초 만에 저장이 끝나고 홈 화면 숫자가 즉시 바뀌는가?
3. **메뉴 성적표 확인**:
   - 메뉴 수익성 탭에서 어떤 메뉴가 '⭐ 효자 메뉴'로 선정되었는지 마진 순위가 한눈에 들어오는가?
4. **월말 예상 손익의 현실성**:
   - 이번 달 남은 날의 예상 매출과 월말 예상 순이익이 사장님의 체감과 맞게 산출되는가?
5. **발주서 복사 버튼**:
   - `[발주서 텍스트 복사]`를 누르고 카카오톡에 붙여넣었을 때 거래처 사장님께 보낼 양식이 깔끔하게 써지는가?
6. **엑셀 백업**:
   - `[데이터 백업]`을 눌렀을 때 엑셀 파일이 다운로드되고, 엑셀 프로그램에서 시트별로 깔끔하게 열리는가?
